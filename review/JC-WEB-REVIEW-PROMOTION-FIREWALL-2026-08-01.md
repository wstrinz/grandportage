## Durable read

The review's central distinction is right and should remain part of GP's
design discipline:

```text
native checker / Lean: is this proposition true in the declared object?
GP: does that proposition license this conclusion in the next context?
```

GP can prevent a correctly scoped local result from becoming an unsupported
source, component, field, coverage, nonlinear, or global claim. It cannot
repair a false theorem inside one correctly declared object unless a small
independent evidence verifier or Lean theorem exposes the error.

That division explains the recent JC corrections:

| Correction class | GP role |
|---|---|
| conditional normalized-root seam promoted toward actual source | current GP refusal; source edge is absent |
| weighted-degree bound promoted to covered row-window control | refuse without an exact support/frame transform |
| symbolic `G` dropped in Laurent rows 7--8 | current finite Laurent lowering can detect the object-level mutation |
| fixed point/fiber obstruction promoted to a component | current restriction/coverage semantics refuse the promotion |
| 24 S4 seed misses promoted to confinement of all `K`-points | witness is local NONEMPTY; bounded miss earns no EMPTY |
| false constant-coefficient annihilator theorem | outside current transport semantics; needs native/Lean recurrence checking |
| first-order incompatibility promoted to nonlinear/global exclusion | current GP refuses the untyped jump; a future narrow jet contract could state the valid one-way implication |

The operational conclusion is stronger than "use GP occasionally": any result
that changes a truth front door, execution plan, or coordinator handoff should
carry either a GP authority ledger or an explicit declaration that the
object-level result is outside GP's present semantics.
